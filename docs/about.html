About vanilla.penplotter

I built this engine because I wanted a drawing written in JavaScript to reach the pen on my iDraw. I also wanted to see the route before the machine started.

Why

I wanted to keep drawing, route planning and the machine connection in the same browser page. The sketch supplies points and pen assignments; the engine turns those into a plan you can inspect.

vanilla.penplotter stores points in layers, with a tool for each layer. It can tidy those paths, choose nearby strokes and estimate the duration. You can export the result or run it through the EBB driver. Direct plotting still needs a dry run, a parked carriage and confirmation.

Where it stops

  • Not a drawing library. It has polyline primitives, simple fills and a limited SVG importer. Curves are sampled into points; there is no text layout or polygon boolean support. Draw with p5.js, p5.gysin, Paper.js or plain arrays; hand the points over.
  • Not p5.plotSvg. p5.plotSvg captures a p5 sketch as an SVG and covers far more of p5's drawing API. It deliberately stops there. This engine can import supported SVG paths and basic shapes, plan them and plot them. Check the preview: it does not reproduce every SVG feature.
  • Not vpype. vpype is the mature reference for line sorting, merging and simplification, in Python, on the command line. The optimizer here is the browser-sized version of the same ideas.
  • Not a universal driver. One machine profile has been plotted with. Everything else exports SVG, HPGL or G-code and stays honest about it.

The machine

Development and physical tests use an iDraw HSE / A2 with EBB firmware 3.0.2. Its CoreXY axes and 80 steps per millimetre were checked on paper on 2026-09-21. The 594 × 432 mm travel comes from the vendor configuration. There is no automatic homing: park the carriage at the home corner before plotting.

The EBB driver checks bed bounds, plans acceleration and handles acknowledgements. On abort or error it attempts to clear motion, lift the pen and release the motors. The example panel can resume after completed strokes of the same drawing; pausing and resuming within a stroke are not implemented.

Two libraries, one direction

If you draw in p5.js, p5.penplotter supplies the draw-and-record object. Planning and machine code stay in this engine. The adapter checks a minimum core version; that check does not prove every possible version combination.

How this was made

I use AI to build bridges, not cities. This library is a bridge: between a drawing in code and a pen, between a plan in millimetres and a board that only knows steps, between a sketch that moves and a sheet that does not. The conversations that built it connected things I could not connect before. They never replaced the pleasure of coding; that stays mine, and so does the responsibility for what is here.

I designed and directed it and wrote it with AI assistance. I check changes in code and on my plotter; the responsibility for the library and its documentation stays mine.
