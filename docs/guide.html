Guide

Start with a line and a circle. Preview the drawing and export it, or check a dry run before sending it to the plotter. The later sections cover pens, fills and route planning.

Twee manieren van werken

Je kunt eerst een volledige tekening maken en die daarna plotten. Je kunt ook één object tekenen, het plotten en pas daarna het volgende tekenen. In beide gevallen krijgt de machine een afgebakende job. Het verschil is wanneer jij beslist dat de tekening klaar is.

Alles tekenen, dan plotten

Je tekent alle lijnen en vormen, bekijkt het geheel en start één plot. De planner kan de route binnen die job ordenen. Kies strategy: "drawn" als de volgorde waarin je tekent ook op papier moet blijven staan.

Eén object tekenen en plotten, dan het volgende

Je tekent een object, plot het en wacht tot de job klaar is. Dan maak je een nieuwe opname voor het volgende object en plot je opnieuw, op hetzelfde papier. Zo groeit het werk terwijl je verder tekent. De planner kent telkens alleen de huidige job; hij kan de route niet over toekomstige objecten heen verbeteren.

Na een plot blijft de opname bestaan. Opnieuw plotten zonder die opname te wissen tekent ook de vorige objecten opnieuw. Dat kan bewust zijn, bijvoorbeeld voor een tweede passage. Voor alleen het volgende object begin je een nieuwe opname. Wat al op papier staat, blijft daar staan.

Dit is werken in opeenvolgende jobs. Nieuwe lijnen aanleveren terwijl de machine nog tekent is live streaming; dat is nog niet geïmplementeerd. Een object kan één lijn zijn, maar ook een groep vormen die je samen wilt plotten.

In vanilla.penplotter

Voor één volledige tekening voeg je alle objecten aan één engine toe. Voor opeenvolgende objecten maak je per job een nieuwe PlotterEngine met dezelfde documentunits en papierpositie. De driver en verbinding kunnen blijven bestaan. De core heeft geen adapter-plot.clear(); een nieuwe engine geeft je een leeg document.

// Elke oproep begint een nieuwe opname met dezelfde pagina.
function nieuwObject() {
  return new PlotterEngine({
    units: "mm", page: { width: 210, height: 297, margin: 12 }
  });
}

const eerste = nieuwObject();
eerste.rect(20, 20, 60, 40);
// Controleer de preview en dry run, bevestig en plot eerste.plan().
// Wacht op status "complete" voordat je het volgende object plot.

const volgende = nieuwObject();
volgende.circle(140, 100, 25);
// Controleer en plot volgende.plan(), op hetzelfde papier.

Dit fragment bouwt twee afzonderlijke documenten en stuurt niets naar hardware. De voorbeeldpanelen tonen één huidige job. Een eigen toepassing kan opeenvolgende jobs uitvoeren via dezelfde driver, telkens na dry run en bevestiging. De standaarddriver keert na een voltooide job terug naar home. Na een stop of fout controleer je de machine en parkeer je opnieuw bij home.

1. Draw and preview

Save this complete page as index.html and open it through localhost or HTTPS. It draws a line and a circle on a canvas, then prints the plan statistics. No plotter is needed. The import pins the source used by this guide.

<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>My pen drawing</title></head>
<body>
  <canvas id="preview" width="420" height="594"></canvas>
  <script type="module">
    import { PlotterEngine } from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/vanilla.penplotter.js";

    const plot = new PlotterEngine({
      units: "mm", page: { width: 210, height: 297, margin: 12 }
    });
    plot.line(20, 20, 190, 20);
    plot.circle(105, 145, 52);
    const canvas = document.getElementById("preview");
    plot.drawRoute(canvas.getContext("2d"), { showTravel: true });
    console.log(plot.plan().stats);
  </script>
</body>
</html>

For the fragments below, keep this page and replace or extend the drawing inside its module block. Core coordinates are document units: here, millimetres. circle() takes a radius. Change 52 to 26 and reload.

The active layer starts as default. Geometry is stored directly; no canvas or SVG has to exist first.

2. Export the drawing

After drawing, export the same plan as SVG. HPGL and G-code need commands and settings suited to the receiving software and machine; exporting a file does not mean the library can drive that machine directly.

plot.drawRoute(canvas.getContext("2d"), {
  showTravel: true
});

const svg = plot.exportSVG();
const hpgl = plot.exportHPGL({ unitsPerMm: 40 });
const gcode = plot.exportGCode({
  penUp: "M5",
  penDown: "M3 S1000"
});

3. Dry run, then plot

Direct plotting has been tested on one machine: the iDraw HSE / A2, an AxiDraw-style CoreXY plotter with an EBB board. The plan goes straight to it; nothing is written to disk on the way.

First open the 40 × 25 mm test and use its dry run. To check your own drawing without hardware, add these imports at the top of the starter's module, then run the commands through the log transport:

import { EbbDriver, compileEbbPlan, createLogTransport }
  from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/src/driver/ebb.js";

const commands = compileEbbPlan(plot.plan(), { profile: "idraw-hse-a2" });
const driver = new EbbDriver({ transport: createLogTransport(), profile: "idraw-hse-a2" });
const result = await driver.run(commands, { confirmed: true });
console.log(result); // commands checked and logged; no serial connection

The example panel handles physical connection, sheet placement, confirmation and stopping. Use it for a first physical test. A custom application can use createWebSerialTransport() and EbbDriver; open the port from a user click and run only after checking the dry run and confirming the job. See Architecture for the driver contract.

Use millimetres, centimetres or inches. Park the carriage in the home corner by hand first: the machine has no homing, so that spot is 0,0 of the plan. Every point is checked against the 594 × 432 mm travel before the first byte is sent, and driver.abort() or an error requests the stop sequence: motion halted, pen up, motors off. A working connection is needed to deliver those commands. compileEbbPlan(plan) with createLogTransport() is the dry run.

Web Serial needs Chrome or Edge on localhost or https. Motion is planned with acceleration; the plan's drawSpeed and travelSpeed are what the machine gets, and run(plan, { drawSpeed, travelSpeed, acceleration, travelAcceleration, junctionDeviation }) overrides any of them. The example panel can resume after completed strokes of the same drawing, after manual parking at home. There is no mid-stroke pause or resume. Exports for other machines need suitable software and configuration.

A complete drawing is prepared before plotting. strategy: "drawn" can preserve its order. Live drawing, where new strokes arrive while the pen runs, is proposed work and has no current API.

The HSE profile records manufacturer defaults separately from its operating settings. It retains the controller's pen calibration unless you supply penLift. For a known standard servo, height percentages are 0–100 and lift/lower rates are 1–100:

import { compileEbbPlan } from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/src/driver/ebb.js";

const compiled = compileEbbPlan(plot.plan(), {
  profile: "idraw-hse-a2",
  penLift: { up: 60, down: 30, raiseRate: 75, lowerRate: 50 }
});

These heights are control percentages, not millimetres. Check the installed servo and pen mounting; omit penLift to keep existing calibration. The machine notes distinguish the tested HSE/A2 from likely compatible devices. Sharing EBB firmware alone does not establish mechanical compatibility.

Paper and drawing size

Paper, drawing and bed have separate sizes. A4 is 210 × 297 mm in portrait, or 297 × 210 mm in landscape. The drawing occupies only the area covered by its strokes. The bed is the machine’s working area; “A2” in a model name does not set your drawing’s size.

PlotterEngine.paperSize(format, orientation, units) exposes the same helper as the named paperSize() export. The p5 adapter uses it to fit a canvas with createPlot({ paper: "A2", margin: 12 }). The core's own paper selection preserves the original stroke size.

import { PlotterEngine, paperSize } from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/vanilla.penplotter.js";

const plot = new PlotterEngine({
  units: "mm",
  page: { ...paperSize("A4", "landscape"), margin: 12 }
});

paperSize() supports A0–A6. It sets the sheet dimensions without scaling the geometry. A3 is 297 × 420 mm; A2 is 420 × 594 mm. On the 594 × 432 mm HSE/A2 bed, A2 fits with its 594 mm edge along X, at X = 0 and Y between 0 and 12 mm.

In every example’s pen panel, choose the drawing’s original page or an A format. A formats start in portrait. Turn by 90° or 270° for landscape, then use Centre paper on the bed or enter X/Y from home. Turning rotates the drawing with its sheet; choosing paper never scales the strokes. The panel blocks plotting if the sheet extends beyond the bed or the drawing extends beyond the sheet. A2 landscape centres at X = 0, Y = 6 mm. Export links keep the drawing’s original page and coordinates, before bed placement.

Cleanup and route planning

plot.optimize({
  duplicateTolerance: 0.01,
  mergeTolerance: 0.05,
  simplifyTolerance: 0.03
});

const plan = plot.plan({
  strategy: "nearest",
  drawSpeed: 40,             // mm/s; chosen operating settings, not vendor defaults
  travelSpeed: 40,
  acceleration: 800,         // mm/s², the estimate ramps like the machine
  travelAcceleration: 300,
  liftDelay: 0.6,            // s per stroke: pen down, and up again
  toolChangeDelay: 15
});

console.log(plan.stats);

Tolerances, coordinates and distance statistics use document units. Planner speeds use mm/s; G-code feed rates use mm/min. HPGL and G-code exports convert coordinates to physical units (96 CSS pixels = 1 inch). SVG retains the document units.

After editing the document, export, statistics and preview rebuild stale plans automatically, retaining the previous optimization and planning settings. This also covers edits to returned paths, layers and tools. Document data must remain JSON-serializable.

More drawing fragments

Use the HTML wrapper from the first step. Replace its module contents with the wave example below. The following fragments reuse its plot object; provide the points or SVG text they refer to. The full example pages include the preview and pen panel.

A wave on A4, as SVG

import { PlotterEngine } from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/vanilla.penplotter.js";

const plot = new PlotterEngine({ units: "mm", page: { width: 210, height: 297, margin: 15 } });
for (let row = 0; row < 20; row += 1) {
  const points = [];
  for (let x = 20; x <= 190; x += 0.5) {
    points.push({ x, y: 40 + row * 11 + Math.sin(x * 0.08 + row * 0.5) * 4 });
  }
  plot.polyline(points);
}
const link = document.createElement("a");
link.href = URL.createObjectURL(new Blob([plot.exportSVG()], { type: "image/svg+xml" }));
link.download = "waves.svg";
link.click();

Tone from lines

const cell = (x, y, size) => [{ x, y }, { x: x + size, y }, { x: x + size, y: y + size }, { x, y: y + size }];
for (let index = 0; index < 8; index += 1) {
  plot.hatch(cell(20 + index * 22, 40, 20), { spacing: 6 - index * 0.65, angle: Math.PI / 4 });
}

Supported SVG paths, planned

import { PlotterEngine, Geometry } from "https://cdn.jsdelivr.net/gh/seb-prjcts-be/vanilla.penplotter@9f19656703c94dc970c0233135cdc9a66cda3f3f/vanilla.penplotter.js";

const imported = Geometry.importSVG(await (await fetch("drawing.svg")).text(), { curveSteps: 24 });
const fitted = Geometry.transformDocument(imported, Geometry.Matrix.scale(0.25)); // 800 px → 200 mm
const plot = new PlotterEngine({ units: "mm", page: { width: 210, height: 297 } });
for (const layer of fitted.layers) plot.layer(layer.id).paths = layer.paths;
console.log(plot.stats());

Use the modules directly

Import from src/geometry, src/optimizer, src/planner or src/renderer. Each stage accepts and returns the documented data objects. You can use these modules separately from PlotterEngine.

Core reference

CallUnits and result
new PlotterEngine({ units, page })Creates an engine and document. Use explicit units and page dimensions; the starter uses millimetres.
line(), circle(), polyline()Coordinates use document units. Circle takes a radius; polyline takes points. Geometry is added to the current layer.
paperSize(format, orientation, units)Returns A0–A6 dimensions; defaults to portrait and mm. Also exposed as PlotterEngine.paperSize(). Does not scale geometry.
optimize(options), plan(options)Cleanup uses document-unit tolerances. Plan returns one PlotPlan; nearest is greedy, drawn preserves path order and direction. Speeds are mm/s.
drawRoute(context), drawBed(context, options)DrawRoute previews planned routes. DrawBed previews machine moves with bed and sheet dimensions in millimetres.
exportSVG/HPGL/GCode/JSON()Return strings from the current plan. HPGL and G-code convert to physical units; machine commands require configuration.
EbbDriverSeparate driver and transport. Physical tests cover the iDraw HSE/A2 only. Compile and log a dry run before a confirmed physical job.

For snapshots, SVG limits, placement and machine profiles, read Architecture. For complete runnable drawings, open Examples.
